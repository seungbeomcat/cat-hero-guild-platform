도살장 V3 → V4 데이터 이관

V3 운영 DB를 읽어 백업한 뒤, V4의 879 · 도살장 길드로 복사하고 다시 대조합니다. 관리자·길드 전용주소·초대코드는 건드리지 않습니다.

일회성 마이그레이션 도구 · V1.0.3

1. 연결 및 관리자 확인

이관에는 역할이 서로 다른 3개의 인증 세션을 사용합니다. ① V4 중앙관리자는 879 · 도살장의 정확한 guildId를 찾기만 합니다. ② V4 도살장 관리자는 그 길드의 실제 운영 데이터를 읽고 씁니다. ③ V3 원본 관리자는 기존 도살장 Firebase를 읽습니다. 세 세션은 모두 메인 계산기 로그인과 분리된 임시 세션이며, 메인 계산기의 로그인 상태를 바꾸지 않습니다.

3. V4 대상 확인

대상 길드를 찾지 않았습니다.
V4의 관리자 문서, 길드 전용주소(accessHash), 관리자 초대코드는 이관 대상이 아니며 수정하지 않습니다. 중앙관리자 세션은 대상 guildId 확인에만 사용하고, 실제 운영 데이터 쓰기는 V4 도살장 관리자 세션으로만 실행합니다.
